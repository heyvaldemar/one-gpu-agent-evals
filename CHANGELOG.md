## [Unreleased]

### Added

- `loadgen/calls.py`: the flagship's `scripts/capacity.py`, from its verified release and unchanged, with every call it makes (its level, seed, start on the wall clock, seconds, outcome and tokens) and every level's unrounded wall time written to a record. Nothing is written while a level is timed: a level's calls are written and fsynced after the level ends, so no write is part of any call's time; a level cut short is measured again whole ([ADR 1](docs/decisions/0001-measured-on-a-workstation-recomputed-in-ci.md)). The flagship's session pointed out that the first version, which fsynced each call as it finished, put that write inside the timed window.
- `scripts/recompute.py`: every level's aggregates computed again from those records with capacity.py's formulas and its own percentile function, imported from the release, failing on any difference and on records that are not whole. `tests/recompute.sh` runs it on a stub server's series and on four damaged copies, and `tests/recompute-plants.tsv` breaks the recorder and the recomputation six ways, each of which the test notices.
- `sources.lock` and `scripts/sources.sh`: the flagship's release v1.9.0, read only after its sha256, its cosign signature and its SLSA provenance pass. `models.lock` and `scripts/models.sh`: weights by the flagship's lines, from the publisher at the pinned revision, refused on another sha256 or a licence that is not a permissive OSI one. `images.lock`: the flagship's server, Python and busybox images by its digests ([ADR 2](docs/decisions/0002-the-flagships-load-server-and-weights-as-released.md)).
- `scripts/validate.sh`: five static checks (`pins`, `models`, `args`, `deploy`, `kind`) that hold this repository to the flagship's release, and `tests/static-plants.tsv`, nine breaks, each of which they notice. `models` also holds every line of `models.lock` to its format: a file at a 40-hex revision, a sha256, a permissive OSI licence, and the flagship's image digest or `unpinned`, which the README explains.
- `tests/e2e.sh` on kind: the flagship's CPU server with the release's arguments and weights, the load from a Job beside it, the pod's own hash of the weights and a control pod that must refuse them under another hash, every level recomputed from its records, the load the flagship's AWS runs measure with (28 request bodies, sha256 603153b0..., as its session computes it; each series records it), and every pod's image one `images.lock` names. `tests/plants.tsv` breaks it five ways.
- `workstation/isolation_check.py`: what the environment on the workstation must not be able to do (a host filesystem, a host mount, a host program, a credential, an address off its list), each tried as root beside a control that must succeed. `tests/isolation.sh` runs it in a closed container and in eight opened ones, each of which it must name; `tests/isolation-plants.tsv` breaks it seven ways, each caught. The first version flagged the test's own bind mount of the check as a host filesystem, rightly; the check now comes in on stdin.
- [ADR 3](docs/decisions/0003-the-host-lends-the-gpu-the-environment-holds-nothing.md), proposed: how a series runs on the workstation, in an environment that holds nothing, with the GPU lent by the host, surviving a power cut.
